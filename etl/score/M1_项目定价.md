## 0 一句话结论

**「三阶含金量最高」不是靠调参数调出来的，是靠结构保证的。**

把 `G` 从「跨项目的绝对幅度」改成「项目内的相对强度」，含金量就只由 `w_e` 决定，
而 `w_e` 里三阶写死是 `1.00`，是全部 21 个项目里唯一的最高值。
`G` 再怎么变，都只能在项目内部调整「这一段算强还是弱」，动不了项目之间的价格。

| 保证 | 数学形式 | 是否依赖数据 |
|---|---|---|
| 典型段单价 三阶最高 | `p_e = w_e`，`w_333 = 1.00` | 不依赖 |
| 单段上界 三阶最高 | `p_max = R_CAP · w_e` | 不依赖 |
| 同段数成就 三阶最高 | `S_e(k) = w_e · k` | 不依赖 |
| 排序与 `w_e` 逐位一致 | `p_e > p_f ⇔ w_e > w_f` | 不依赖 |

这四条已写进 `test_runs.js` 的 [7][8][9][10] 四项断言，改坏一条测试就红。

## 1 问题：`G` 原本在做一件它做不到的事

`G = ln(前一位留下的值 / 本段最好值)` 回答的是**「这条路还能往前推多远」**。
但「推得远」有两种完全相反的来源：

- **路快走完了**（三阶卷了 21 年）→ 每步只能磨几个百分点；
- **路还长**（冷门项目离物理极限远）→ 随便一练就是三成。

直接拿 `G` 跨项目比价，等于把「这条路没人走」当成「这个人强」。
实测（单次轨，中位 G）：四盲 20.46%、二阶 17.11%、金字塔 14.23%
对 四阶 3.00%、七阶 3.63%、SQ1 3.96%，
极差 6.8 倍。

### 1.1 三条错误修法，以及为什么都不行

**错误一：给 `w_e` 扩量程。** 看似直接，但算一下需要多大：

归一前，一条「典型二阶 WR」的价是 0.16，一条「典型三阶 WR」只有 0.0514，
二阶是三阶的 **3.06 倍**。要把它压到 1 倍以下，
`w_222` 必须 ≤ 0.300（现值 0.92）。

更极端的是四盲：一条典型 WR 是 3.2 条三阶，需要 `w_444bf` ≤ 0.251。
照这个推下去，整个 `w_e` 表会被压进 0.3141～1.00 之间，量程 3.2 倍。
**结果不是「三阶最高」，是「除三阶以外全部接近零」** —— 换一种方式否定项目多样性。

**错误二：只修一半，用 `ρ_e^α` 打折。** 之前提过按「项目活跃人数占比」缩放，实测这条路走不通 ——
因为 `ρ_e` 根本分不开「主流项目之间」的竞争强度：

| 项目 | 活跃人数（相对三阶） | 归一前典型价（倍三阶） | 压平所需的 α |
|---|---|---|---|
| 四盲 | 0.302 | 3.1841× | 1.0 |
| 二阶 | 0.948 | 3.0628× | ≈ 21 |
| 金字塔 | 0.853 | 2.4917× | 5.8 |
| 五盲 | 0.218 | 1.8414× | 0.4 |
| 三盲 | 0.646 | 1.3887× | 0.8 |

二阶的活跃人数是三阶的 0.948 倍 —— 几乎一模一样，因为 detail 层前 2,500 名几乎人人参赛所有主流项目。
**要用人数打折压住二阶那 3 倍，α 得取 21 —— 等于把这个项目直接删掉。**
金字塔也要 α ≈ 6。α 是全局参数，取最大值才管用，于是整张表全废。
而四盲虽然人数只有三阶的一半，α 也要 1.0 才压得住。
所以 `ρ_e^α` 只能在「深渊项目」上起作用，对主流项目完全无效。**这条路的量程不够，不是参数没调好。**

**错误三：保留 `G` 的绝对值，只调 `w_e` 的次序。** 这动摇不了结论 —— 只要 `G` 还跨项目，
`w_e` 的次序就永远在和 `G` 的次序打架，谁赢取决于具体选手碰上哪个项目。

## 2 正确修法：完全归一（α = 1）

```
r        = min( G / G_ref(e), R_CAP )        // 项目内相对强度
credit   = r × min(T, D_cap) / 365           // 占有段口径不变
score    = credit × w_e × V_L × ρ_s × f_L   // w_e 是唯一的跨项目价格
```

`G_ref(e)` = 该项目 `G` 的算术均值（两轨各算各的）。`R_CAP = 3`。

### 2.1 为什么用算术均值：一个恒等式

```
Σ_i ( G_i / mean(G) ) = n
```

这与分布形状完全无关，含长尾也成立。含义是：

> **任何项目的历史总信用 = 该项目的段数。** 一个「段」在所有项目里完全同质。

于是「三阶是否最贵」只取决于 `w_e`，与 `G` 实测分布完全解耦。这是整个方案的关键。

实测校验：

|---|---|---|---|---|---|

| 四盲 | 11.4460 | 13 | -1.5540 | 5.0000 | 5 |

### 4.3 为什么「项目历史总池」不是含金量

若把每个项目历史上全部 WR 段的信用加起来（`w_e × Σr`），排序是：

| 项目 | 历史总池 | 段数 S/A |
|---|---|---|
| 四阶 | 56.1 | 36/30 |
| 单手 | 51.2 | 27/36 |
| SQ1 | 45.8 | 34/25 |
| 三盲 | 44.6 | 30/29 |
| **三阶** | **41.8** | 27/19 |
| 二阶 | 37.5 | 14/27 |
| 魔表 | 33.9 | 26/25 |
| 五阶 | 30.9 | 23/18 |

三阶排第 5。这不是含金量输了，是**段数输了**：总池 = `w_e × 段数`，
段数由「这个项目历史上被破了多少次」决定，是活跃度，不是含金量。

而且 12 条截断对三阶伤害最大 —— 三阶 WR 条数全站最多，被砍掉的比例最高。
现在三阶只剩 27 段（单次轨），全量数据下会大幅回升。相比之下四盲只有 13 段，本来就少，几乎没被砍。

所以这一列**现在不可用**，等全量阶梯导出后才能解释。

## 6 副作用与未决

1. **`R_CAP = 3` 是设计选择，不是推导结果。** 它决定「一次惊人突破能顶几段」。
   调大 → 奖励单次爆发；调小 → 奖励稳定迭代。取 3 的依据是实测 r 的 P90 约 2.5～8，
   3 落在「削掉最极端的一小截」的位置。
   当前被截顶的段共 47 / 748（6.3%）。
2. **`w_e` 明显偏窄。** 活跃项目的量程是 1.0000 → 0.7700，只有 **1.2987 倍**；
   连停办项目一起算也只有 1.00 → 0.5800（1.7241 倍）。
   如果你要「三阶明显高于其他」，需要重标定 `w_e` 本身（价值判断，不是校准）。
   这一步现在可以放心做，因为 `G` 已经不再和它打架。
3. **`w_e` 表本身没有数据依据。** 它是手写的递减表。归一之后它成了唯一的价格来源，
   所以「它凭什么这样写」变成必须回答的问题 —— 建议按项目活跃人数或人均参赛次数重标定。
4. **`G_ref` 用全量还是滚动。** 现在用历史全样本均值，意味着一个新项目（如 2020 年后才有的项目）
   的早期段会被后期段拉低参考。严格做法是按年滚动，但会引入时间维度，暂不做。
5. **段数问题仍未解。** 「同段数三阶最高」已经保证，但「不同段数怎么比」还没定。
   现在靠占有段口径的 `T`（持有时间）吸收了一部分，但一个项目被破 44 次 vs 28 次，
   历史总产出确实不同。这属于「活跃度」而非「含金量」，建议不修正。
