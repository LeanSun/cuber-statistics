**一条纪录值多少分，不看「破了几次」，看「把纪录推低了多深」× 「独占这条纪录多少天，直到被别人打破」。**

## 1 计分公式（唯一权威）

```
score = Σ_段 [ r × min(T, 30年)/365 × V_L × ρ_s × f_L × w_e ]

  G       = ln(前一位留下的值 / 本段最好值)          推深幅度（对数）
  r       = min(G / G_ref(项目,轨道,级别), 3)        项目内归一
  T       = 本人持有到被别人打破的天数               由事实决定，不设固定窗口
  V_L     = 级别价值（见 §2）
  ρ_s     = 该级别该属地的竞争密度
  f_L     = 该持有区间内的时代折算均值
  w_e     = 项目权重（见 §2）
```

**核心恒等式**：`Σ(G_i / mean(G)) = n` —— 任何项目的历史总信用恒等于段数，
因此**一个段跨项目完全同质**，这是选算术均值而非中位数的唯一理由。

## 8 封存时仍未接入生产（重要）

**M1-F1 是离线引擎，站点现在显示的还不是它。**

`etl/build.js` 目前完全没有 `require('etl/score/runs.js')`，生产链路的 `m1` 仍是**旧条数口径**：

```js
// etl/build.js:721
const m1s = (p.wrS || 0) * 3 + (p.crS || 0) * 1.5 + (p.nrWS || 0) * 0.8;
const m1a = (p.wrA || 0) * 3 + (p.crA || 0) * 1.5 + (p.nrWA || 0) * 0.8;
```

即「破了几次 × 固定权重」，与占有段口径毫无关系。接入需要：

1. `build.js` 引入 `runs.js`，在 `computeModules()` 里对每人算占有段分
2. 阶梯必须**全局先建**（跨选手），不能按人循环 —— 需要一趟预扫描
3. `MOD_MAX.m1` 的归一化分母要重标定，否则 0–100 区间会整体压缩（现在最高 83.71，旧口径分位完全不同）

**这一步属于 M2 之后的工程任务，不在 M1 封存范围内。**

## F2b · 2026-10-26 重跑：ρ 分母对齐（基线替换）

### 触发

排查 Feliks 三阶 M1 时发现：站点 `M1_facts.tsv`（冻结于 2026-10-25 22:58）与
当时磁盘上的 `js/data.js` / `js/roster.js` **不同源**。表现是 CR/NR 两项系统性偏高：
站点表隐含 **ρ_OC ≈ 0.0908**，而按 10-26 重建后的池子算是 **0.048208**，差 1.88 倍；
WR 项只差 1%（f_L 漂移）。结构四项（records 55,244 / 阶梯 4,822 / 段 25,270 / 有分 4,952）
两次完全一致 —— 是 `R.total`（ρ 的分母）变了，不是计分逻辑变了。

> 根因：ρ_s = 属地人数 ÷ **全站选手总数**，而全站总数来自 `js/roster.js` 的 `R.total`。
> 名册每重建一次，历史 CR/NR 分数就整体改一次比例 —— **这是个非平稳量**。

### 处理

按「数据重建 → M1 → 六维 → 建站」的顺序重跑一遍并收敛：

```
node --max-old-space-size=8192 etl/build.js --zip data/raw/WCA_export_v2_288_20261015T000017Z.tsv.zip --slim-max 60000
node --max-old-space-size=8192 etl/score/m1_hold.js
node --max-old-space-size=8192 etl/score/sixdim.js --csv sixdim        # 双轨 + site + by_event + js/sixdim_data.js
node --max-old-space-size=8192 etl/score/sixdim.js --track single --csv x
node --max-old-space-size=8192 etl/score/sixdim.js --track avg    --csv x
node --max-old-space-size=8192 etl/build.js ...（再建一次，把新 p.six 注入 data.js）
```

`m1_hold.js` 现在是**幂等**的（连续两次跑的 `M1_facts.tsv` md5 一致 `2f189b30…`），
说明已到达不动点：名册 239,783 + 明细 60,274 = 300,057，与 `R.total` 自洽。
