> 2026-10-25 · 诊断脚本 `etl/score/m5_f1_probe.js` / `m5_f1_compare.js` / `m5_f1_depth.js` / `m5_f1_decide.js`

## 0 一句话

F1 用「近 365 天窗口内的实际最好成绩」重排名，**修好了 M5 最严重的语义缺陷**（衰减惩罚错了对象），
但它同时把 M5 推向「纯现势快照」—— 这是收益也是代价，需要你拍板。

---

## 1 问题回顾：P1「衰减惩罚错了对象」

M5 当前用官方 `ranks_*.tsv` 的 `world_rank`。这个榜是 **「按 PB 排序的终身榜」**：

> 一个 2019 年跑出 16 步的人，只要这 16 步没被超越，2026 年仍显示 `333fm|single` **#1**。

M5 加了退役衰减 `decay(gap)`，gap = 「在该项目内末次参赛距今」。但这个衰减：

| | 条目数 | 占 M5 总贡献 |
|---|---:|---:|
| 衰减**确实**惩罚了（停赛 ≥2 年） | 116 | 1.3% |
| **衰减完全失效**（还在参赛，但 PB 已 ≥2 年未刷新） | **617** | **15.9%** |

→ 衰减的作用面只有 1.3%，**15.9% 的贡献来自「名次是几年前刷出来的僵尸名次」**。

---

## 2 F1 方案定义

```
F1 = Σ_{e,t} w_e · rank_window(e,t)^-1.0 · [decay(gap)]
```

`rank_window` = 该选手在**近 N 天窗口内**的实际最好成绩，在同一 (项目,轨道) 组合内的排名。

- 窗口内**没参赛** → 该组合直接 0 分（退役者自动出局，不需要衰减来救）
- 窗口内**还在打** → 名次由近期真实表现决定

窗口长度 N 的实测敏感性（详见 §5.3）：365 / 730 / 1095 天，**Top5 完全相同**，N 选 365。

## 3 ⚠️ 实现陷阱：必须用「序号口径」而非「同名次」

这是 F1 落地时踩到的最大坑，值得单列。

官方榜用「并列同名次」（4 个 16 步同为 #1，下一个是 #5）。如果窗口重排名沿用这个规则：

| 组合 | 窗口内人数 | 同名次口径下「≤100 名次」条目 | 序号口径 |
|---|---:|---:|---:|
| `222\|single` | 39,461 | **1,620** | 100 |
| `333fm\|single` | 3,276 | **3,276**（全部！） | 100 |
| `pyram\|single` | 27,651 | **715** | 100 |
| **33 组合合计** | — | **12,227** | **3,268** |

**同名次口径会让 `DEPTH=100` 的深度截断完全失效** —— 12,227 条目远超 33×100=3,300 的理论上限。
根因：窗口内成绩**并列极密集**（`333fm|single` 3,276 人挤在约 14 个步数值上），
`333fm` 干脆全部 3,276 人都是 #1。

**解法**：窗口口径用**序号口径**（第 i 名 = 序号 i），同值按「达成日 → 姓名」定序。
这一条已写进主脚本 `m5_current_rank.js` 的 `winRanks` 构建逻辑，并有注释警示。

## 5 各方案细节

### 5.1 F1 修好了什么

**关键案例 `333fm|single`**（最少步）：

| 名次来源 | 选手 | 成绩 | PB 首次达成 | 365 天窗口内最好成绩 |
|---|---|---:|---|---:|
| 官方 #1 | Sebastiano Tronto | 16 步 | **2019-06-16** | **19 步** |
| 官方 #1 | Aedan Bryant | 16 步 | 2024-06-23 | 18 步 |
| 官方 #1 | Levi Gibson | 16 步 | 2024-06-23 | 20 步 |
| 官方 #1 | Jacob Sherwen Brown | 16 步 | 2024-10-26 | 23 步 |
| **官方 #5** | Brian Johnson | 17 步 | 2026-05-02 | **17 步** |
| **官方 #5** | Baiqiang Dong (董百强) | 17 步 | 2026-06-07 | **17 步** |

官方榜：4 个 2019–2024 年的 16 步并列 #1，其中 Tronto 的 7 年前成绩还霸着榜。
**窗口榜：Brian Johnson 等一批 2026 年跑出 17 步的人才是当前最快** —— F1 把他们提到 #1。

**窗口 #1 的官方名次分布**（33 组合，365 天窗口）：

```
#1×26    #2×5    #3×1    #5×1
```

即：**26 个组合的窗口第一就是官方第一**（这些项目本来就活跃且没被打破），
**7 个组合的窗口第一在官方榜上不是 #1** —— 这 7 个就是 F1 纠正的对象。

### 5.2 F2（PB 新鲜度）修好了什么

F2 对 P1 那 617 条「活跃但 PB 陈旧」的条目，总贡献从 **14.8058 → 7.6111（−48.59%）**。

典型案例：

| 选手 | 项目 | 官方名次 | PB 年龄 | V0 贡献 | F2 贡献 |
|---|---|---:|---:|---:|---:|
| Oleg Gritsenko | `555bf\|single` | #99 | 12.7y | 0.0030 | 0.0006 |
| Feliks Zemdegs | `333oh\|single` | #43 | 11.4y | 0.0145 | 0.0030 |
| Kaijun Lin (林恺俊) | `333mbf\|single` | #63 | 10.6y | 0.0049 | 0.0010 |
| Roman Strakhov | `555bf\|average` | #25 | 9.6y | 0.0121 | 0.0025 |

F2 的特点是**精准但保守**：它只压低「陈旧名次」的权重，**不改变名次本身**。
Top25 与现状重合 23/25（比 F1 的 21/25 更稳），且 **×M4 ρ = −0.0576**（比 V0 的 0.0532 更正交）。

### 5.3 窗口长度的敏感性

| 窗口 | 窗口 #1 ≠ 官方 #1 的组合数 |
|---|---:|
| 365 天 | **7** / 40 |
| 730 天 | 2 / 40 |
| 1095 天 | 1 / 40 |

窗口越长越接近官方榜。365 天捕捉到的「现实与榜单的背离」最多，
而 365 / 730 / 1095 的 Top5 **完全相同** → 窗口长度**不是敏感参数**，取 365 天（近一年）最直观。

### 5.4 F1 对 esum 重复度的影响

M5 × 站点 `esum` 的 ρ：

| 口径 | ×esum ρ |
|---|---:|
| V0 现状 | 0.3980 |
| F1s 窗口 | **0.3482** |
| F1b 窗口 | **0.3459** |
| F2 | 0.3861 |

F1 让与 esum 的重复度**下降约 0.05** —— 因为 esum 用的还是官方终身榜名次。
**但这不改变「esum 必须被 M5 取代」这个结论**：两者结构仍然高度相似，不能同时计入总分。

## 8 三方案对比与建议

| 维度 | F1（窗口重排名） | F2（PB 新鲜度衰减） |
|---|---|---|
| 改动量 | 中（需自建排名） | **极小**（改 gap 定义一行） |
| 语义 | 「你最近表现如何」—— 纯现势 | 「你的名次有多新」—— 名次仍是终身榜 |
| 修正 P1 | ✅ 彻底（名次本身就换了） | ✅ 精准（权重降 48.6%） |
| 人口变动 | ~500 人（20%） | **0 人** |
| Top25 稳定性 | 21/25 | **23/25** |
| ×M4 正交性 | 0.1153~0.1243 | **−0.0576**（最好） |
| ×esum 重复度 | **0.3459**（最低） | 0.3861 |
| 新增旋钮 | 窗口长度（不敏感，365 即可） | 无 |
| 与 M1–M4 的关系 | 更「当下」，与历史维度区分更清晰 | 名次仍带历史惯性 |
| **主要代价** | **M5 变成纯快照，年年变**；与「世界排名」的官方定义脱钩 | 名次本身仍是化石榜，语义问题只缓解未根治 |

### 我的建议

**先不急着换。** 理由：

1. **F1 与 F2 修的是同一个病，但 F2 的代价几乎为零**（人口不变、Top25 重合 23/25、
   ×M4 正交性反而最好）。F1 的 20% 人口换血，是**用榜单稳定性换语义纯度**，
   在 M5 还没接入 `build.js`、六维总分还没定权重之前，这个交易不划算。

2. **F1 把 M5 彻底变成现势快照**，这与「M1–M4 历史 / M5 当下」的分工是一致的，
   但也意味着 **M5 每年会重排**。如果六维总分里 M5 权重不小，快照的年际波动
   会传导到总榜 —— 需要先想清楚「总分是否应该含现势项」。

3. **两个方案不冲突**。可以先上 F2（低风险、立即生效），
   把 F1 作为「窗口档」留在代码里（`RANK_MODE = 'window'`），等六维权重定了再决定切不切。

> **如果你更看重「M5 就该是当下的真实实力」而不是「榜单稳定」**，
> 那就切 F1 —— 语义上它确实更对，代码也已经落地可用。

## 10 踩坑记录（勿再犯）

1. **`wr = 0` 的条目会穿透深度检查**。窗口重排名时若把未赋名次的条目（`wr` 初始 0）留在表里，
   `it.wr > CFG.DEPTH` 判定为 `0 > 100` = false → **全部放行**。
   实测污染成 60,509 人 / 总量 Infinity。**必须 `list.slice(0, lim)` 显式截断。**
2. **同名次口径会冲破深度截断**（12,227 vs 3,300 上限）—— 见 §3。
3. **`pearson()` 返回裸数字**，不是 `{n, rho}` 对象。写成 `s4.rho` 会得到 `undefined` → `NaN`。
4. **`b.m5 - a.m4` 是从 M4 复制来的死代码**（M5 的 `perPlayer` 没有 `m4` 字段）→
   `undefined` → `NaN` → 落到排序的第二项。功能上侥幸正确，但会误导读者，已清理。
5. **`winBest` 的 key 是 `窗口|轨道`**，但内部又是 `ev|tr` 两层 ——
   取的时候必须 `winBest.get('365|single').get('333fm|single')`，
   直接 `winBest.get(365)` 会得到 `undefined`。
6. **`persons.tsv` 第 3 列才是 `wca_id`**（第 1 列是姓名）——
   `pName.set(r[2], r[0])` 的方向不能搞反。
7. **F1 独立诊断脚本与主脚本的实现必须能互相对上**：
   独立脚本给出 3,268 条目 / 1,239 人 / 90.8582，主脚本 window 口径给出完全相同的三个数 ✓
   —— 这是 F1 实现正确性的交叉验证。
