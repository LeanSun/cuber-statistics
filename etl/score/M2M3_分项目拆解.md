# 分项目拆解：项目之间的账是分开的

> 现算，源 WCA v2.0.2，脚本 `etl/score/diag_event_split.js`。只读，不改任何常量。
> 内核与 `m2m3_balance.js` 一致（S4 口径：年代本地 REF + hill(500) + WC 全球池 + α = 0.5000）。

**结论先说**：模型在**每一条领奖台**上就分了项目，五魔的分进不了三速。
总分只是「各项目账本相加」，筛选就是把账本按项目抽出来。

══ 0 一张图看懂：分是怎么分到项目上的 ══

```
一条领奖台（某人 · 某场 · 某项目 · 前三）
   → 只属于该项目的账本
   → 单条分 = P(名次) × K(赛级) × 规模项 × f(年代) × w(该项目权重) ×（普通赛再乘 β×n^-0.5）
                └────────── 全部按该项目算 ──────────┘

选手的「三阶分」= 他所有三阶领奖台的单条分之和
选手的「五魔分」= 他所有五魔领奖台的单条分之和（与三阶无关）
选手的「总分」  = 各项目分相加
筛选 {三阶, 五阶} = 只把这两个项目的账本加起来
```

| 层 | 是否按项目分开 | 位置 |
|---|---|---|
| 单条计价（REF、w_e、规模项） | ✅ 本来就是 | `refOfEra(ev, year)` / `EV_WEIGHT_V2[ev]` |
| 重复衰减 n（同人第 n 次） | ✅ 分组键 = `pid\|ev` | `m2m3_balance.js` 衰减段 |
| 账本（选手 × 项目） | ✅ 本文档拆出 | `pid\|ev` 单元格 |
| 总分 | 只是各项目相加 | 筛选时按需求和 |
| β / K / α（价格常量） | 全局常量，不分项目 | 筛选不改变价格 |

**β 在筛选时不变**：β 是「普通赛单条 ÷ 锦标赛单条」的价格比，不是「某项目占多少」。
只看三阶时，三阶普通赛单条仍然 × β，价格体系不因筛选而变。

══ 1 零交叉验证：五魔进不了三速 ══

三步硬校验（任一不成立即说明有串分）：

1. **可加性**：每人「各项目分之和」= 总分
   - 全站 20,716 人，最大误差 = 0.0000（浮点误差量级）
2. **删除检验**：把五魔全部领奖台删掉，重算三阶分——必须一字不差
   - Feliks 五魔领奖台 74 条、五魔分 22.7933
   - 他的三阶分：含五魔 59.6928 / 删光五魔 59.6928 / 差 = 0.0000
3. **衰减隔离**：五魔的第 n 次普通赛，不影响三速第 n 次的衰减
   - Feliks 五魔普通赛 58 条，三阶普通赛 138 条
   - 三阶的第 1 次衰减恒为 1.0000、第 2 次 0.7071…，**与五魔条数无关**（分组键 `pid\|ev`）

> 一句话：项目在**最底层**就是分开的，「总分」只是后加的账本合计。

══ 6 给站点的数据结构（筛选要的就是这个） ══

每个选手存一份「项目账本」，筛选时对选中项目求和即可。

```js
player.evScore = {
  "333":  { total: 87.31, m2: 62.10, m3: 25.21, n: 41, gold: 12 },
  "555":  { total: 41.02, m2: 33.50, m3:  7.52, n: 18, gold:  7 },
  "minx": { total:  3.14, m2:  2.20, m3:  0.94, n:  4, gold:  1 },  // 五魔的分只在这
  ...
}

// 筛选：选中项目求和（价格常量 β/K/α 不重算）
function scoreOf(player, evSet) {
  let s = 0;
  for (const ev of evSet) s += (player.evScore[ev] || {}).total || 0;
  return s;
}

// 单项目榜 = 按该 ev 的 total 排序
// 多项目榜 = 按 scoreOf(player, evSet) 排序
// 领奖台列表：每条 podium 自带 ev 字段，按 ev 过滤即可
```

**三个不要做的操作**：
1. 不要按项目重解 β —— β 是普通赛/锦标赛的价格比，与项目无关
2. 不要把五魔条数并进三速的 n —— 会让三速的第 2 次领奖台被错误衰减
3. 不要在筛选后重算 REF —— REF 是「该项目同时代典型人数」，已经是项目维度的

══ 7 诚实的边界 ══

- **跨项目的「可比性」靠 w_e 维持，不是靠混账**：三阶冠军 ≈ 五魔冠军的 1/0.86 倍，
  这个比价写死在 w_e 里。只看五魔时人人乘同一常数，排名不变；跨项目比较时才显出贵贱。
- **组合筛选不等于重新排名**：「三阶+五阶」的第 1 名可能既不是三阶第 1 也不是五阶第 1，
  但那是两个账本相加的结果，不是新公式。
- 尚未接入 `build.js`（站点仍在旧口径）。本拆解的数据结构是给接线用的参考实现。
- greater_china 的 5 场仍按洲锦赛计，会影响那几条的赛级标签（不影响项目归属）。
- 多盲（333mbf）的规模项沿用人数口径（与其它项目一致），未单独特殊化。
