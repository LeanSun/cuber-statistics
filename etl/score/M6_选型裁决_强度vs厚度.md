## 1. 决定性证据：厚度与「M4 历史版」的相关系数是 0.898

用年度榜重建「历史 M4」= `Σ_格 domScore(当年名次) × 事件权重 × log(1+占席年数)`，然后算相关矩阵：

```
                    M1纪录      M2领奖台       M4现势      M4历史版         厚度         强度
M1纪录             1.000      0.495      0.177      0.371      0.372      0.014
M2领奖台           0.495      1.000      0.245      0.403      0.451      0.065
M4现势             0.177      0.245      1.000      0.502      0.496      0.323
M4历史版           0.371      0.403      0.502      1.000      0.898      0.475
厚度               0.372      0.451      0.496      0.898      1.000      0.464
强度               0.014      0.065      0.323      0.475      0.464      1.000
```

**ρ(厚度, M4历史版) = 0.898** —— 两者本质是同一个东西。

这在数学上很自然：厚度（每年保持在前 100 的年数）和「历史 M4」（每年名次的 domScore 时间积分）都是
**「按年度、按项目，衡量长期占位」**。差别只是连续刻度 vs 计数刻度。

**所以厚度不是一个新维度，它是 M4 缺的那一半。**

## 2. 附带重大发现：现 M4 根本没有历史维度

build.js:761-794 的 M4 实现是：

```js
const wr = worldRank.get(id) || {};
Object.keys(wr).forEach((eid) => {
  const rk = o && o.r ? o.r : 0;      // ← 现势世界名次（快照）
  const ds = domScore(rk);
  m4 += ds * w;
});
```

`worldRank` 来自 `ranks_single.tsv` —— **只有今天的名次，没有时间轴**。

三项验证：

| 检验 | 结果 | 含义 |
|---|---|---|
| ρ(m4, 现势最优名次倒数) | **0.685** | m4 基本是现势名次的函数 |
| ρ(m4, 生涯年数) | 0.178 | 与持续时间几乎无关 |
| 按生涯起点分组的 m4 均值 | 2.2 / 2.4 / 2.3 / 2.9 / 2.8 / 2.5 / 2.6 / 2.5 / 2.4 / 3.0 / 2.8 … | **从 2003 到 2025 起点的选手，m4 均值几乎完全一样** |

对照组：厚度按同一分组是 **18.2 → 13.4 → 8.0 → 5.4 → 3.3 → 1.3 → 0.2**，单调递减，符合直觉。

**结论：用户定义的 M4「统治力（在某项目上保持世界第一保持了多久被打破）」在系统里是空的。**
现在站上展示的 m4 实为「当前名次的 domScore 换算」，与「统治力」不是一回事。

> 附带发现：`months1 / months10 / months100 / peakSpan / peakAge` 五个字段在 build.js:880、1160 里是
> **硬编码 0**，全站所有选手都是 0，前端 `js/app.js:45` 也照样下发。是**死字段**。

## 3. 厚度的三个结构性问题（为什么不能当独立 M6）

### 3.1 与 M2 中度相关（偏相关控制密度后仍存在）

- ρ(厚度, M2) = **0.451**
- 控制参赛密度 `comps` 后：**ρ = 0.223**（仍非零，说明不是纯密度伪影）

对比：ρ(强度, M2) = **0.065**；控制 `comps` 后 **ρ = −0.006** —— 几乎完全正交。

### 3.2 被参赛密度驱动

进 top100 的样本平均当年参赛 **5.19 场**，未进的只 **2.26 场**（2.29×）。
分层命中率：参赛 1 场 → 0.6%；16–31 场 → 14.4%。

「每年都有成绩」本身就是进入前 100 的必要条件，而非额外能力。

### 3.3 国家生态偏差（修复 yTop100 后复核）

厚度 Top20 国家富集：

| 国家 | 人数 | 富集 |
|---|---|---|
| Hungary | 2 | **11.38×** |
| Netherlands | 2 | 10.98× |
| Denmark | 1 | 8.78× |
| Sweden | 2 | 6.75× |
| Germany | 2 | 5.25× |

强度 Top20 国家富集：

| 国家 | 人数 | 富集 |
|---|---|---|
| Poland | 4 | **5.74×** |
| Hungary | 1 | 5.30× |
| United Kingdom | 2 | 4.05× |
| Malaysia | 1 | 3.88× |

强度偏差幅度约为厚度的一半，且集中在真正强国（波兰/匈牙利/马来），
而厚度的富集来自「赛事密度高的小国」。

### 4.3 定稿口径 T

```
strength[pid|event|year] = 该选手在 (项目, 年代) 池内的成绩分位
oppQ(r)   = 被击败对手在同 (项目, 年代) 池内的分位均值
excess(r) = oppQ(r) − 同 (项目, 年代, 赛级) 的中位基线
M6_i      = Σ_r excess(r) × w(r)        w = 1 / 0.6 / 0.4（冠/亚/季）
```

**聚合不乘任何 n^±α** —— 次数归 M2，M6 只管质量。
ρ(M6, M2) = **−0.0106**，完全正交。

## 5. 落地建议（按优先级）

### P0：M4 重做（真正的缺口）
用户定义的 M4「统治力 = 保持世界第一多久被打破」目前是空的。
现实现 = `domScore(现势名次)`，无历史维度。

**两个可选口径：**
- **A. 纪录持有段**（推荐）：M1 已有完整的持有段机制（Ownership-Run），
  直接把「持有多久」提取为独立 M4，语义最贴用户定义，且与 M1 的「持有价值」可拆分。
- **B. 历史占席积分**（= 厚度升级）：用年度榜 `domScore` 时间积分 × 年数，
  即本报告的「M4历史版」。已有现成原料（`thick_boards.json` 418 格）。

> A 与 B 的差别：A 测「巅峰的持续」，B 测「长期在前沿」。若用户要的是「统治力」，
> **A 更准**；B 覆盖更广但含 M2 的成分。

### P1：M6 = 对手强度
复用 `etl/score/m6_strength.js`（已跑通，18.8s / 1.36GB），可并入 `build.js:597` 同一次扫描，
净增约 +5.6s / +400MB。

落地前必做：
1. 把 `ρ(M6, M2) < 0.3` 写成回归断言；
2. multi 类项目（333mbf/333mbo）解码与 `build.js` 的 `fmtVal()` 对拍；
3. 单项目榜 Top20 人工核对（已做，见 4.1）。

### P2：M4 历史化后，厚度作为 M4 的子指标
`yTop100`（已修复）继续保留并展示，作为「多年世界前 100」；
但**不作为独立评分维度**，避免与 M1/M2/M4 三重重复。

## 6. 五个坑（强度方案，实测踩出）

1. **`pos` 不是名次**，是轮次内卡位（最大 912）。只有 `round_type_id ∈ {f, c}` 才是最终名次。
   反例：WC2019/333 的 `f` 轮 Max Park pos=4（他是季军）、Weyer pos=1（他是冠军）。
2. **分位方向**：q 写反成 `i/(n−1)` → 「击败弱对手」变最高分 → Top25 全是只打过 1 场的无名选手。
3. **multi 类项目**（333mbf/333mbo）成绩是编码值，直接比大小会错乱。
4. **时代归一必须自建历史排名** —— `ranks_*.tsv` 是现势快照；两版 Top50 只重叠 23/50。
5. **必须扣赛级基线** —— oppQ 中位 WC 0.9516 / CC 0.7409 / OP 0.7284，不扣就把 M2 算两遍。

同一人占多个名次槽位 → `yTop100` 按人头重复计数。
