# M6 设计：六维评判标准下的「强度」维度

> 生成时间：2026-10-25
> 背景：用户重设六维评判标准（M1 纪录分 / M2 领奖台 / M3 大赛表现 / M4 统治力 / M5 当前排名 / M6 待定），
> 要求 M6 **适合单项目评价**。
> 口径：新六维是**重新设计**，与 `docs/GOAT模型_定稿_v1.0.html` 的旧 M1–M7 不同名同义，需分开看。
> 数据源：`data/raw/WCA_export_v2_288_20261015T000017Z.tsv.zip`（v2.0.2，2026-10-15）

---

## 0 一句话结论

**M6 建议做「强度」：衡量这个人击败/超越的对手当时有多强。**

理由：M1–M5 全部在回答「**做了多少 / 做了多久 / 现在如何**」，
**没有一维回答「这件事到底有多难」**。M3 只判「大赛 vs 普通」的场合差异，
判不了「这一场的对手到底强不强」——这是唯一的空缺格。

## 1 诊断：M1–M5 的覆盖矩阵

| 维度 | 产出了什么（量） | 在什么条件下（质） | 维持了多久（时间） | 现在如何（现状） |
|---|---|---|---|---|
| M1 纪录分 | ✓ 刷新次数 | — | — | — |
| M2 领奖台 | ✓ 冠亚季军次数 | — | — | — |
| M3 大赛表现 | — | ◐ 只判「大赛/普通」 | — | — |
| M4 统治力 | — | — | ✓ 第一在位时长 | — |
| M5 当前排名 | — | — | — | ✓ |

**空缺**：整个「质」这一列没有真正的度量。
现有 M2 里的折算因子（`T_L` 赛级 / `ρ_s` 属地规模 / `f_L` 时代）全是**赛事属性**，
不是**对手属性**。ρ_s 问的是「这个国家/洲有多少人参赛」，不是「这些人本身多强」。

### 1.1 数据验证：规模与强度是两条独立的轴

全站决赛（`round_type_id='f'`）前 3 名构成领奖台，取同场另两位领奖者的世界排名倒数均值
`V(r)=r^-1.1` 作为对手池强度（`ranks_single` 现势排名，仅用于验证信息独立性）：

| 赛级 | 样本 | 对手强度中位 | 25% | 75% | 「最强对手排不进前 1000」占比 |
|---|---|---|---|---|---|
| WC 世锦赛 | 172 | 0.0033 | 0.0006 | 0.0538 | **33.7%** |
| CC 洲锦赛 | 492 | 0.0052 | 0.0009 | 0.0347 | 26.2% |
| NC 国锦赛 | 8,419 | 0.0007 | 0.0002 | 0.0030 | 56.6% |
| OP 公开赛 | 101,402 | 0.0006 | 0.0002 | 0.0019 | 64.7% |

**两个反直觉的发现：**

1. **CC 的对手强度中位（0.0052）反而高于 WC（0.0033）。**
   世锦赛决赛的亚军季军常是外洲尖子——在本洲是 No.1，在世界榜上却排几百名。
   规模（人数）大 ≠ 对手强，两者排序可以完全相反。
2. **连世锦赛都有 33.7% 的领奖台，最强对手排不进世界前 1000。**
   全站 110,485 条冠军领奖台里，**27,177 条（24.6%）**的最强对手排到 5,000 名开外
   （例：2012 Tibet Open 冠军击败的对手世界排名 287,473）。
   M1–M5 对这 24.6% 完全无感——它们和「击败世界前 5」在 M2 里只差一个名次权重。

## 2 推荐方案：M6 · 强度（Opponent Strength）

### 2.1 定义

> **M6 衡量：这个人做成的每一件事，是在多强的对手面前做成的。**

单条成就 `i`（一条纪录或一次领奖台）的对手池强度系数：

```
Φ_i = ( 1 / |O_i| ) · Σ_{j ∈ O_i} V(r_j)          V(r) = r^-γ,  γ ≈ 1.1
O_i = 该场该项目中，除他以外的全部决赛选手
```

单条得分乘 `Φ_i`，模块聚合：

```
M6 = Σ_i  base_i · Φ̃_i
Φ̃_i = Φ_i / median{ Φ : 同项目 · 同年代 · 全部决赛 }     ← 时代归一
```

**为什么要 `Φ̃`（相对化）**：`V(r)` 天然随年代衰减——2005 年世界前 50 是世界前 10 级别，
2026 年前 50 只是前 50。除以同期中位数后，`Φ̃` 变成「这场决赛的对手比同期典型决赛强多少」，
量纲是**倍数**（1.0 = 典型），不随年代漂移，也就不与 M1 的 `f_L` 重复。

### 2.2 为什么这个口径在单项目评价下最自然

- 单项目的世界只有那几百号人，**击败谁 = 实力**，没有跨项目可比性问题
- 天然防刷分：打软对手刷再多条，`Φ̃` 趋近 0，与 M2 的 `i^-0.5` 幂律是**互补**而非重复
- 数据现成：`results.tsv` 有同场同项目全部选手名次 → 构造对手池无需额外数据源
- 对 M1 也有反哺作用：`Φ̃` 可以直接作为 M1 纪录段的乘子，让「在小场子里刷的 WR」自动贬值

### 2.3 相关性检验（8,700 名领奖台 ≥5 条的选手，Spearman）

| 配对 | ρ（single） | ρ（average） | 判定 |
|---|---|---|---|
| **M6候选 × 平均决赛人数（规模代理）** | **+0.121** | **+0.130** | 几乎完全正交 ✅ |
| M6候选 × 大赛领奖台条数（WC+CC） | +0.300 | +0.291 | 正交 ✅ |
| M6候选 × 冠军数 | +0.513 | +0.509 | 中等相关 ⚠ |
| M6候选 × M2 领奖台条数 | +0.654 | +0.650 | 未超 0.7，但偏高 ⚠ |
| *对照*：冠军数 × M2 领奖台条数 | +0.838 | +0.838 | **重复计分** ❌（现有模型的既有问题） |

- 判定阈值沿用旧手册 §5.2：**|ρ| > 0.7 即视为重复计分**
- 两条排名口径（`ranks_single` / `ranks_average`）结论一致，**不是噪声**
- 与「规模」ρ = 0.12 是决定性证据：M6 不会重复 M2 的 `ρ_s`

### 2.4 头部名单差异（Top20 重叠仅 30%）

| 只在「领奖台条数」Top20 | 只在「对手池强度」Top20 |
|---|---|
| Feliks Zemdegs、Bence Barát、Jan Bentlage、Niko Ronkainen、Daniel Wallin、Juliette Sébastien、Alwin Rölz、Daniel & Martin Vædele Egdal | Max Siauw、Noah Swor、Chris Chi、Mark Boyanowski、Rowe Hessler、Mason Langenderfer、Zeke Mackay、Lim Hung、Graham Siggins、Yiheng Wang、Paul Mahvi |

左边是「**数量型**」——奖拿得多；右边是「**质量型**」——每次都从世界前 20 里杀出来，
但总量不多。**M6 的价值就是把这两种人区分开**——这正是纯数量榜做不到的。

### 2.5 落地要点

1. **首选实现：项目内 Bradley–Terry / Elo**（比 Φ̃ 更规范）
   - `results.tsv` 同场同项目同轮次的名次天然构成 head-to-head 对战对
   - 拟合 BT 得到项目内 Elo，再用「对手 Elo 均值」作强度
   - 旧模型的 M7 声称做 Elo，但 `build.js` 里实际实现的是
     「名次在该项目参赛人数中的相对位次」——**那不是 Elo**，是个粗糙代理
2. **次选实现：Φ̃ 直接算**（无需拟合，30 分钟能出数）
3. **时代归一是必须项**，否则 `Φ̃` 会把「2005 年击败世界前 30」和「2026 年击败世界前 30」
   判成同一件事，而这恰恰是 M1 的 `f_L` 已经在处理的时间维度——不归一就是重复计分
4. **后视偏差警告**：`ranks_single` / `ranks_average` 是**现势**排名。
   定稿口径应自建**时间序列排名**（`build.js` 已有 `worldRank` 的日粒度遍历思路可复用），
   否则「2015 年的对手强度」会被 2026 年的排名改写

## 3 备选方案

### 3.1 备选 A：相对分位 Z（同期同项目标准化水平）

```
z_{p,e,t} = ( 成绩 − 同期同项目均值 ) / 同期同项目标准差
```

- **优点**：极简，跨年代天然可比，单项目下最"正统"，实现成本最低
- **缺点**：
  - 同期分母含大量「只比过一次的新手」，均值被严重拉低，z 分布左偏严重
  - 与 M1 高度重合（老 M1 的 `r = G/G_ref` 本质就是相对突破幅度）
  - 衡量的是"相对位置"而非"绝对水平" —— 一个人在自己时代的第 50 名会拿到高 z
- **适用**：如果只想要一个能快速上线的维度、且不愿投入对手网络构建

### 3.2 备选 B：突破幅度 / 单次纪录质量（Peak Gain）

```
G_i = ln( 前值 / 本段值 )        r = min(G / G_ref, 3)
```

- **优点**：直接回答"这次突破值不值"；M1-F1 已有现成实现
- **缺点**：与 M1 几乎完全重合，作为独立维度会**自己跟自己重复**
- **适用**：不作为独立维度，而是作为 M1 的内部乘子（这正是 M1-F1 现在的做法）

### 3.3 备选 C：生涯厚度（老模型 M6）

```
M6_old = B_Y·ln(1+活跃年数) + B_N·ln(1+累计场次) + B_S·ln(1+破纪录跨度)
```

- **优点**：现成（`build.js` 已有 span / comps / activeStreak）
- **缺点**：
  - **单项目评价下几乎失效**——生涯厚度是跨项目的量，单项目筛出来后没有信息
  - 与 M1/M2 的累计性质高度重合（打得久 → 破得多、拿得多）
  - 老手册自己也知道，所以 M6_old 在序数定权里排最后（权重 ~2%）
- **结论**：这正是用户旧模型 M6 被淘汰、现在空出来的原因。**不建议回填。**

## 4 顺带两条建议

### 4.1 M3「大赛表现」建议做成 M1 的内嵌乘子，而不是独立加法项

M3 的内容（锦标赛刷新纪录额外加分）本质是 **M1 产出 × 场合权重** 的交互项。
若作为独立维度相加：
- 它与 M1 强相关（没有纪录就没有大赛纪录）
- 会给 M1 分配两份权重，破坏 M1 内部的排序

**更干净的两种做法**：

| 做法 | 形式 | 优点 |
|---|---|---|
| 方案 a：内嵌乘子 | M1 每条纪录 × (锦标赛 ? 1.3 : 1.0) | 不占序数权重，不破坏排序 |
| 方案 b：对称 Clutch | `Cl = z̄_锦标赛 − z̄_公开赛`，可为负 | 大赛掉链子会被扣分，不只奖励 |

方案 b 正是旧手册 M6 的 `Cl_p` 写法，**可以正负对称**，
比"只奖励不惩罚"更接近"大赛表现"这个词的本意。

### 4.2 M4 与 M5 都是排名维度，建议 M4 用连续积分而非只看第一

- **M4**（历史：世界第一保持多久）与 **M5**（现状：当前排名 + 退役衰减）
  建立在**同一个原始量（世界排名）**上，存在天然相关
- 建议 M4 扩成**排名席位的时间积分**（一条 `r^-λ` 曲线同时覆盖第一在位月数、
  前十累计月数、前 100 占席），`build.js` 里的 `domScore()` 已经是这个分段线性版本
- **M5 的退役规则**（5 年不参赛视为退役，排名折算到不参赛的第 5 年）方向正确，
  但要显式写死「只衰减不归零」：退役选手的历史 M1–M4 应完整保留，
  只有 M5 这一个现状项随时间衰减。否则会出现「退役 = 抹掉历史」的荒谬后果
